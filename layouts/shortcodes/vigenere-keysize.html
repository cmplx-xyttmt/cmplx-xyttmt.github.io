The answer

Reveal: why Hamming distance finds the key length (open only after you've tried)

At the correct keysize, the two bytes in a column were encrypted with the same key byte. XOR-ing them cancels the key:

c1 ⊕ c2 = (p1 ⊕ k) ⊕ (p2 ⊕ k)
        = p1 ⊕ p2 ⊕ (k ⊕ k)
        = p1 ⊕ p2            (because k ⊕ k = 0)

So you are really XOR-ing two English letters. English letters cluster in a narrow byte range (lowercase a–z all share the high bits 011xxxxx), so p1 ⊕ p2 has few 1-bits → low Hamming distance.

At a wrong keysize, the two bytes used different key bytes, so the key does not cancel:

c1 ⊕ c2 = p1 ⊕ p2 ⊕ (kA ⊕ kB)

Now kA ⊕ kB is a nonzero constant that scrambles the result toward random → more 1-bits → higher Hamming distance.

Dividing by K makes keysizes comparable; averaging over many block pairs smooths the noise. Multiples of the true keysize dip too, because a repeated key (key vs keykey) is equally valid — bytes 2K apart still share a key byte.

Bytes vs Strings

A string is text for humans. Bytes are numbers a computer does math on. Cryptography lives entirely in the bytes world. Type below and watch text cross the border into bytes, hex, and base64.

The key idea: the byte list, the hex, and the base64 above are all the exact same bytes — three costumes for one set of numbers. Hex isn't "what bytes are"; it's just a convenient way to write them down.

Where does each character go?

A str is a sequence of characters (code points). Encoding turns each character into one or more bytes. For plain English it's 1:1, so bytes and text feel interchangeable — but emojis and accents break that.

Things a string knows that raw bytes don't

A str understands characters as whole units, no matter how many bytes they take. Raw bytes are just a flat pile of numbers — they've forgotten where one character ends and the next begins.

# One emoji is ONE character but FOUR bytes s = "🔥" len(s) → 1 # str counts characters len(s.encode()) → 4 # bytes counts bytes list(s.encode()) → [240, 159, 148, 165] # Slicing bytes can rip a character in half — producing garbage s.encode()[:2] → b'\xf0\x9f' s.encode()[:2].decode() → UnicodeDecodeError! # Text operations (case, etc.) only make sense on str "caf\u00e9".upper() → 'CAFÉ' b"caf\xc3\xa9".upper() → b'CAF\xc3\xa9' (bytes .upper() only touches ASCII)
The one sentence to keep: bytes are numbers you do math on; str is text for humans; .encode()/.decode() convert between them via an encoding (default UTF-8), and you only convert at the edges of your program.

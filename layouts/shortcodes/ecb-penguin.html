The ECB penguin

ECB encrypts each block independently and deterministically: the same input block always gives the same output block. So anything with repeated or uniform regions — like a picture — keeps its structure through "encryption". A proper mode makes every block come out different, so the same picture becomes noise. In the ECB panel the colours are scrambled, but the penguin is still there. Uniform regions (all-white background, the black body) are made of identical blocks, so ECB maps them to identical output blocks — the shape is preserved. Shrink the block size and it sharpens; grow it and it gets chunkier, but the outline never disappears. The proper-mode panel has no repeats, so it is pure static.

What this is really showing

This is the Challenge 8 signal, made visible. "Repeated plaintext block → repeated ciphertext block" is why you could detect ECB by searching for duplicate 16-byte blocks — and it is exactly why an image betrays its outline here.

How the simulation works (it's honest about the mechanism)

Each panel chops the image into blocks. For ECB, every block is coloured by a hash of its own pixels — deterministic, so two identical blocks get the identical colour (just like AES-ECB gives identical ciphertext for identical plaintext). For the proper mode, each block gets a fresh random colour regardless of its contents, so equal regions no longer look equal. That single difference — deterministic per-block vs randomized — is the whole story.
